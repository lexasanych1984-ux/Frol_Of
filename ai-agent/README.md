# Trading Discipline AI

AI-операционная система дисциплины трейдера. Не торгует и не предсказывает рынок — контролирует риск-лимиты проп-счёта, находит повторяющиеся поведенческие ошибки, обогащает существующий Notion-журнал сделок объективными данными из MT5.

## Идея

- Источник субъективных данных — Notion-журнал (`Trading Journal`): сетап, эмоции, причина входа.
- Источник объективных данных — MT5 (пока ручной экспорт истории, позже — библиотека `MetaTrader5`).
- Сведение (matching) двух источников по инструменту + времени входа (допуск в несколько минут).
- Риск-модуль под конкретные лимиты проп-счёта (FundingPips) — приоритет №1.
- Периодический AI-разбор через Claude API — поведенческие паттерны, честная оценка размера выборки.
- Telegram-бот как интерфейс. Сейчас он news-only + журнальные помощники:
  `/week`, `/news`, `/sync`, `/trade` (историю `/risk` `/review` `/setup` см. в
  разделе статуса — они удалены из бота 2026-07-09, но доступны из CLI).

## Структура

```
config/                 конфиги (риск-лимиты, id-шники Notion)
src/
  mt5_import/           парсинг MT5 (HTML-отчёты, позже — live через MetaTrader5)
  notion_sync/          клиент и schema Notion API
  matching/             сведение сделок MT5 <-> записи Notion
  risk/                 риск-лимиты и мониторинг
  ai_review/            анализ через Claude API
  telegram_bot/         интерфейс /review /risk
  storage/              локальный кэш (SQLite)
  cli.py                точка входа
tests/
data/raw/               сюда класть выгруженные ReportHistory-*.html
```

## Старт

```bash
python -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # заполнить токены
cp config/config.example.yaml config/config.yaml   # заполнить риск-лимиты счёта
```

Проверить парсер на реальном экспорте:

```bash
python -m src.mt5_import.html_parser data/raw/ReportHistory-XXXXXXXX.html
```

## Команды бота `/trade` и `/sync`

Бот запускается `start_bot.bat` (работает, пока включён ПК). Обе команды сначала
показывают, что собираются сделать, и ждут нажатия «Подтвердить» — без нажатия в
журнал ничего не пишется.

### `/trade` — быстрый лог сделки текстом

```
/trade шорт GER40, вход 24100 стоп 24150 тейк 24000, сетап 1Н поглощение
```

Парсер (`src/trade_log/parser.py`, без LLM) распознаёт направление, инструмент,
вход/стоп/тейк (запятая-разделитель, пробел-тысяч, англ./рус. ключи, тейк
опционален) и сетап. Показывает карточку; по подтверждению создаёт строку журнала
с заполненным полем **Entry** (ключевая цель — сделать `/setup`-статистику
зрячей). Сетап фаззи-матчится по закрытому словарю Entry; при неоднозначности бот
просит уточнить, а не выбирает молча. Цены и план RR пишутся в тело страницы (в
журнале нет отдельных полей под цены). Голосовой ввод (STT) — отдельный будущий
шаг, сейчас только текст.

### `/sync` — импорт закрытых сделок из ручного MT5

```
/sync        # сделки за 30 дней (config: mt5_sync.default_lookback_days)
/sync 90     # за 90 дней
```

Подключается к **ручному** терминалу MT5 (`config.yaml: mt5_sync.terminal_path`,
по умолчанию `C:\Program Files\MetaTrader 5\terminal64.exe`) строго по явному
пути — изолированно от «ботовского»/бэктестового терминала (MetaTrader5 держит
одно подключение на процесс). Терминал должен быть запущен и залогинен, иначе —
понятная ошибка. Собирает закрытые позиции из истории сделок, сверяет с журналом
через существующий matching (символ+дата) и предлагает создать только те, которых
в журнале ещё нет (без дублей). Заполняет объективные поля
(Date/Pairs/Direction/Account/RR-PnL); Result и Entry оставляет пустыми — это
субъективная классификация трейдера, а сетап MT5 не знает.

### Нюанс доступа Notion

Резолв relation-полей при создании требует, чтобы справочник был расшарен
интеграции «Trading AI». Проверено 2026-07-22: журнал, Pairs и Account доступны,
а база **Direction — нет** → поле Direction не проставляется (бот честно
предупреждает). Чтобы включить Direction: открыть базу Direction в Notion →
`Connections` → добавить `Trading AI`.
