При работе с tradingview-desktop MCP (C:\Users\lexas\.claude\tools\tradingview-mcp) инструменты pine_* могут ломаться.

**Why:** `FIND_MONACO` в src/core/pine.js берёт ПЕРВЫЙ `.monaco-editor.pine-editor-monaco` из DOM. Если редактор Pine переезжал между панелями, остаётся «зомби»-контейнер 0×0 без React-фибера → все pine_* падают с «Could not open Pine Editor». Кроме того, `env.editor.getEditors()[0]` может быть невидимым инстансом — pine_set_source пишет код не в тот редактор, и «Обновить на графике» компилирует старый код. Кнопки «Add to chart / Update on chart» MCP ищет по английскому тексту, а UI русский («Добавить на график» / «Обновить на графике») — поэтому smart_compile жмёт только Save и study на графике не обновляется.

**How to apply:**
1. Зомби: через ui_evaluate удалить контейнер с width=0: `document.querySelectorAll('.monaco-editor.pine-editor-monaco')` → `.remove()` у элемента с нулевым rect.
2. Невидимый инстанс: после pine_set_source проверить через ui_evaluate, что видимый редактор (`ed.getDomNode().offsetParent !== null`) содержит новый код; если нет — скопировать `editors[0].getValue()` в видимый `setValue()`.
3. Обновление на графике: кликнуть иконку `lightButton` без текста в шапке редактора Pine (это «Обновить на графике», Ctrl+Enter) через ui_evaluate.
4. Диалог «Сохранить скрипт» может блокировать компиляцию — закрывать кликом по кнопке «Сохранить».
5. Проверять, что study обновился, по содержимому таблицы через data_get_pine_tables (добавлять новую строку-маркер в таблицу при каждой ревизии кода).
