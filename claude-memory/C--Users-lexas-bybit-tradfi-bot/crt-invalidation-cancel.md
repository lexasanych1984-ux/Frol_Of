CRT-вход всегда отложенный (stop/limit) — теперь **не фильтруется по возрасту**
(гейт свежести только для market). Отложка стоит на фикс. уровне, риск не зависит
от возраста сигнала. См. [[silent-failures-history]] (потеря входа 23.07 из-за
75-мин фильтра — то, что этим и чинится).

Инвалидацию CRT-идеи (2 ветки: **закол тенью** за экстремум манипуляции `high>tD1h`/
`low<tD1l`, и **конец дня**) стратегия делает через `strategy.cancel_all()`, а он
**не шлёт alert_message** → бот не видел отмену. Решение (реализовано в коде бота):
- Pine: в 2 точках отмены добавить `alert("CRT ОТМЕНА "+side+ticker, alert.freq_once_per_bar_close)`.
- Бот: `Action.CANCEL` (parser текст+JSON) → `broker.cancel_pending()` (MT5 `TRADE_ACTION_REMOVE`, только ордера по magic стратегии).
- Бэкстоп: `config.yaml → pending_orders.expire=window` — MT5-экспирация отложки в
  конце окна CRT (23:00 МСК), безопасно деградирует к gtc. На случай, если бот
  офлайн и пропустил alert ОТМЕНА.

**Why:** без alert() отмена молча теряется → фантомная отложка живёт вечно (GTC) и
может исполниться через день на мёртвом сетапе. Молчание = авария.

**Как настраивали (на будущее):** MCP `alert_create` умеет только ценовые алерты —
стратегический алерт создаётся руками в UI. Ключевое: копия стратегии на графике
должна быть свежей версии (иначе алерт привяжется к старой и `alert()` не будет).
Пункт «При заполнении заявки и вызове alert()» в диалоге появляется, только если в
стратегии есть `alert()` — это индикатор, что версия на графике правильная.
