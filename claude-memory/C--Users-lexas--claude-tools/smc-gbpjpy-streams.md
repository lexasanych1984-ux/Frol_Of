Следствия, которые легко забыть:

- **Тайм-стопа на GBPJPY нет и быть не может** — патология «позиция висит неделями» там
  не устранена.
- **Решение по полу стопа их не касается:** `useAtrBand=true`, пипсовый коридор перекрыт,
  `minStopPip=20` — мёртвый инпут. Форвард-чекпойнт по полу применим только к EURUSD.
- **GBPJPY 1H — это не «2-е колено»:** maxBos=10 плюс контекст D1. По сути третья стратегия.
- Графиков GBPJPY в TradingView **нет ни одного**; раскладка «вкладки EURUSD / GBPJPY 15м /
  GBPJPY 1ч» в портфельной доке неактуальна. Алертам график не нужен.

⚠️ **Бот не различает два GBPJPY-потока.** Одинаковый тег стратегии (`smc`), magic
(`770001`) и символ MT5 (`GBPJPY`); `close_position` ищет по паре «символ + сторона».
**Выход одного потока закроет позицию другого.** Правка `on_exit_alert: ignore -> close`
(01.08) это окно расширила. До закрытия п.3 тикета
`bybit-tradfi-bot/docs/tickets/2026-08-01-timestop-exit-parsing.md` — две GBPJPY-позиции
одной стороны разбирать вручную. EURUSD не задет, у него свой символ.

**Статистика в доке измерена, формулы «winrate × 3R» там нет** (в отличие от прежних цифр
EURUSD): экспектанси считана как `Net / сделок / средний убыток`. Но **15m не сходится** —
в `data/trades-gbpjpy-15m.txt` пять окон на 55 сделок и +$3269.31, а в доке 61 сделка
и +$3617; одного окна (6 сделок, +$347.69) в файле нет. 1H сходится точно (35 сделок,
+$3391.24). Полного 6-оконного протокола GBPJPY не проходил — только EURUSD.
