# Мониторинг живости бота

**Принцип: молчание = авария.** У бота была история молчаливых отказов (403 на
CDP-хендшейке, мёртвый endpoint TradingView, выключенная кнопка «Алго-торговля» —
узнавали только по отбитому ордеру). Мониторинг делает эти отказы громкими.

Два уровня защиты:

1. **Встроенный health** — внутри процесса бота (`bot/health.py`), проверяет
   4 вещи каждые 5 минут и шлёт Telegram при изменениях.
2. **Внешний watchdog** — отдельный процесс в Планировщике Windows
   (`tools/watchdog.py`), раз в час проверяет, что сам бот жив. Ловит случай,
   когда бот упал целиком вместе со встроенным health.

## Что проверяется (4 проверки)

| # | Проверка | Что значит FAIL |
|---|----------|-----------------|
| 1 | **Поток сигналов** | CDP-соединение с TradingView разорвано, или push-поток завис — нет ни одного кадра дольше `HEALTH_CDP_STALE_SEC` (10 мин). Пропущенные алерты не восстановить. |
| 2 | **Связь с MT5-счётом** | `account_info()` молчит (терминал закрыт/разлогинен), или активен НЕ ожидаемый из `.env` логин (`MT5_LOGIN`). |
| 3 | **Кнопка «Алго-торговля»** | `terminal_info().trade_allowed == False`. Терминал молча рубит каждый ордер (retcode 10027). |
| 4 | **Серверное разрешение советникам** | `account_info().trade_expert == False`. Сервер брокера запретил торговлю советникам. |

## Какие сообщения приходят в Telegram

- `🔴 АВАРИЯ · <проверка>` — немедленно при переходе **OK → FAIL**, с причиной
  и разделом «Что делать».
- `🟢 Восстановлено · <проверка>` — немедленно при переходе **FAIL → OK**.
- `🔴 Всё ещё авария (N мин)` — напоминание о длящейся аварии, **не чаще раза
  в 30 минут** (`HEALTH_ANTISPAM_SEC`).
- `📊 Жив. Аптайм … Проверки 4/4. Сигналов за сутки: N, ордеров: M` — раз в
  сутки в `HEALTH_DAILY_SUMMARY_AT` (09:00 локально).
- `▶️ Бот запущен …` / `⏹ Бот остановлен штатно` — старт и штатная остановка.
- `🛑 ПРОЦЕСС БОТА НЕ ЗАПУЩЕН` — от **внешнего watchdog**, если бот упал.

Ко всем сообщениям добавляется префикс `[BOT]` (`TELEGRAM_PREFIX`).

## Что видно в логах бота (`logs/bot.log`)

На уровне **INFO** (по умолчанию) health пишет только события:
- `health: старт мониторинга — проверки 4/4: signal=OK mt5_login=OK ...` — базлайн при старте;
- `health → Telegram: 🔴 АВАРИЯ · ...` / `🟢 Восстановлено · ...` — каждый переход и факт отправки;
- `health: сообщение НЕ доставлено в Telegram: ...` — **WARNING**, если доставка не удалась (потерянный алерт).

Рутинные тики «ничего не изменилось» пишутся на уровне **DEBUG** (heartbeat
`health: проверки 4/4: ...`) — чтобы INFO-лог не засорять. Хочешь видеть, что
монитор тикает каждые 5 минут — поставь `logging.level: DEBUG` в `config.yaml`.

Читать лог: `Get-Content logs\bot.log -Tail 50 -Encoding UTF8` (UTF-8).

## Настройка Telegram

Переиспользуем существующего бота из `D:\MY\Crypto\AI agent` — секреты не
дублируем. В `.env`:

```
TELEGRAM_ENV_FILE=D:\MY\Crypto\AI agent\.env   # оттуда берутся токен и chat_id
TELEGRAM_PREFIX=[BOT]
```

Либо впиши значения напрямую (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). Если
ничего не задано — бот работает, но уведомления молча выключены (предупреждает
об этом один раз в лог).

## Внешний watchdog (Планировщик заданий)

Регистрация (обычный PowerShell, без админа):

```powershell
powershell -ExecutionPolicy Bypass -File tools\install-watchdog-task.ps1
```

Создаёт задачу «bybit-tradfi-bot watchdog», раз в час. Логика:

- pid-файл (`logs/bot.pid`) есть и процесс жив → молчим;
- pid-файл есть, а процесс мёртв → **бот упал аварийно** → Telegram-тревога;
- pid-файла нет → бот остановлен штатно (он сам удаляет файл и шлёт `⏹`) → молчим.

Вывод чекера пишется в `logs/watchdog.log`. Проверить вручную:

```powershell
Start-ScheduledTask -TaskName 'bybit-tradfi-bot watchdog'
python tools\watchdog.py        # или так, из корня проекта
```

Удалить задачу: `... install-watchdog-task.ps1 -Uninstall`.

## Приёмка

1. **Кнопка алго-торговли off → on.** В MT5 выключи «Алго-торговля» → в течение
   5 минут придёт `🔴 АВАРИЯ · Кнопка «Алго-торговля»…` с точной причиной
   (retcode 10027) и что делать. Включи обратно → `🟢 Восстановлено`.
2. **Падение процесса.** Убей процесс бота (Диспетчер задач / `taskkill`) →
   в течение часа придёт `🛑 ПРОЦЕСС БОТА НЕ ЗАПУЩЕН` от внешнего watchdog.
