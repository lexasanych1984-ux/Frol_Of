# Отчёт эджа и раннее предупреждение о деградации

Система сравнивает **факт демо-форвард-теста** (Just2Trade) с **коридорами
бэктеста** и заранее предупреждает, если эдж поехал. Плюс даёт объективную базу
для будущего решения о переходе на реал: цифры демо против ожиданий, а не «на
глаз». Приоритет проекта — стабильность и наблюдаемость демо (перенос на
Bybit-реал отложен).

## Из чего собрано

| Часть | Файл | Что делает |
|---|---|---|
| Коридоры бэктеста | `expectations.yaml` | диапазоны WR / PF / сделок-в-мес / доли БУ / макс. серии стопов / худшего месяца по каждой стратегии |
| Лог проскальзывания | `logs/executions.csv` | append-only: на каждый вход ПЛАН (цена алерта, риск %, RR) ↔ ФАКТ (цена фила, риск %, RR) + дельта в пунктах |
| Отчёт | `python run.py report` | факт ↔ коридор, пометки OK/ВНИМАНИЕ/ПРОБЛЕМА, сводка слиппеджа, честность выборки |
| Живые тревоги | движок + `bot/edgewatch.py` | два немедленных события (см. ниже) |

Коды модулей: `bot/expectations.py` (загрузка коридоров), `bot/execlog.py`
(лог), `bot/slippage.py` (арифметика риска/слиппеджа), `bot/report.py`
(аналитика и рендер), `bot/edgewatch.py` (живая серия стопов).

## 1. Лог проскальзывания (`logs/executions.csv`)

На каждый вход движок дописывает строку: план из алерта против факта исполнения.
Для **рыночного** ордера факт (цена, объём) известен сразу; для **limit/stop**
факт появляется при срабатывании и досчитывается отчётом из истории MT5 по
`position_id`. Колонки — план (`plan_entry`, `target_risk_pct`, `plan_rr`),
факт (`fill_price`, `actual_risk_pct`, `actual_rr`) и дельта (`slip_pips`,
`slip_pct_of_sl`, `risk_delta_pp`, `adverse`).

«Пункт» здесь — пипс инструмента (EURUSD 0.0001, GBPJPY 0.01, индексы 1.0), а не
MT5-point. `risk_delta_pp` — насколько фактический риск ушёл от заданного, в
процентных пунктах.

Сводный `logs/trades.csv` (его строит `run.py stats`/`report` из истории MT5)
дополнительно обогащается этими же колонками план↔факт по `position_id`.

## 2. Команда `report`

```powershell
python run.py report            # текущий месяц
python run.py report 2026-06    # конкретный месяц
python run.py report last       # прошлый месяц (так зовёт Планировщик)
python run.py report last notify # + краткая сводка в Telegram
```

Что делает: тянет закрытые сделки из истории MT5 (глубина `REPORT_HISTORY_DAYS`,
по умолч. 400 дн.), по каждой стратегии считает **накопительный** факт демо и
сравнивает с коридором. Пишет Markdown в `logs/reports/report-YYYY-MM.md` и
краткую выжимку в консоль; с `notify` — сводку в Telegram.

**Классификация исхода** (по P&L относительно планового риска 1R): `win` ≥ +0.5R,
`stop` ≤ −0.5R, между ними `be` (стоп в безубытке — для CRT это ~2/3 исходов,
норма). 1R берётся из лога проскальзывания по `position_id`, иначе оценивается
медианой убытков стратегии.

**Честность выборки:** если сделок по стратегии меньше `min_sample` (20), отчёт
пишет «⏳ мало данных, выводы преждевременны» и НЕ ставит тревожных вердиктов —
только справочные цифры. FX-ядро даёт ~1.5–2.5 сделки в месяц, поэтому смысл
появляется на накопленной истории, а не по одному месяцу.

**Слиппедж** сводится по символам, отдельно **индексы** (там главный вопрос —
рыночные ордера на быстрых индексах) и **FX**: среднее и худшее проскальзывание,
средняя и худшая дельта риска, сколько входов проскользнули в минус.

## 3. Автозапуск 1-го числа месяца

```powershell
powershell -ExecutionPolicy Bypass -File tools\install-report-task.ps1
# проверить сейчас (сформирует отчёт за прошлый месяц):
Start-ScheduledTask -TaskName 'bybit-tradfi-bot monthly report'
# удалить:
powershell -ExecutionPolicy Bypass -File tools\install-report-task.ps1 -Uninstall
```

Задача Планировщика 1-го числа в 09:05 запускает `run.py report last notify`:
Markdown в `logs/reports/` + краткая сводка в Telegram.

## 4. Немедленные (не месячные) тревоги

Только два события, оба сразу в Telegram (тот же бот, что у мониторинга живости):

1. **Риск сделки выше заданного** — на исполнении фактический риск превысил
   заданный больше чем на `RISK_OVERSHOOT_PP` (по умолч. 0.3 п.п., дефолт из
   `expectations.yaml → meta.risk_overshoot_pp`). Считается движком по реальной
   цене фила рыночного ордера. Ловит случай «рынок ушёл до отправки/фила, риск
   молча раздулся» (реальный инцидент 2026-07-20: 1% → 1.39%).
2. **Серия стопов сверх нормы** — текущая серия стопов подряд по стратегии
   превысила исторический максимум (`max_stop_streak` из `expectations.yaml`).
   Проверяется раз в `EDGE_CHECK_INTERVAL_SEC` (15 мин) по истории MT5.
   Анти-спам событийный: об одной длине серии — один раз; серия выросла — новое
   сообщение; оборвалась (win/BE) — счётчик сброшен.

## Настройки (`.env`, все опциональны — есть дефолты)

```
EXPECTATIONS_FILE=expectations.yaml
EXEC_LOG_FILE=logs/executions.csv
REPORTS_DIR=logs/reports
REPORT_HISTORY_DAYS=400
RISK_OVERSHOOT_PP=          # пусто → из expectations.yaml (0.3)
EDGE_CHECK_INTERVAL_SEC=900
```

## Приёмка

- `python run.py report` отрабатывает на текущей истории демо (пишет Markdown,
  консольную выжимку; при n<20 по стратегии — «мало данных», без ложных тревог).
- Симулированная сделка с завышенным риском триггерит тревогу
  (`tests/test_slippage.py::test_overshoot_triggers_alert`).
- Аналитика (классификация, серии, вердикты, честность n<20) покрыта
  `tests/test_report.py`; лог — `tests/test_execlog.py`; коридоры —
  `tests/test_expectations.py`.
