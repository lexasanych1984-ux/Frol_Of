# TV Config Watchdog — сторож боевых конфигов TradingView

**Зачем.** Конфиги боевых инстансов дважды тихо слетали на дефолты (инцидент
13.07 — EURUSD мог стрелять с чужим риском и фильтрами). Этот сторож делает
такой слёт громким: 2 раза в день сверяет живое состояние 6 боевых
strategy-алертов TradingView с эталоном и шлёт в Telegram при любом расхождении.

**Принцип: молчание = авария.** Если TV недоступен — это тоже уведомление, а не
молчаливый пропуск.

## Что именно сверяется

Источник правды — **замороженные инпуты strategy-алертов** (`list_alerts`), а не
инстансы на графике. Причина: strategy-алерт хранит собственный снимок инпутов;
именно он исполняется на сервере TV и кормит бота/пуши. Инстанс на рабочем
графике — dev-копия (у CRT она вообще другой версии: v23 на графике против v21 в
боевом алерте).

Для каждого из 6 потоков (`etalons.json` → `streams[]`) проверяется:

- **алерт жив** — присутствует среди алертов TV;
- **активность** — `active` совпадает с `expected_active`;
- **символ** и **таймфрейм** — привязка не уехала;
- **pine_id / версия скрипта** — не подменён сам скрипт;
- **каждый инпут** — построчный дифф `in_N`; при различии сообщается
  человекочитаемое имя (из `labels.json`) + было/стало.

## СТРОГО READ-ONLY

Сторож только **читает** (`list_alerts` одним запросом) и **сообщает**. Он
никогда не пишет в TradingView, не меняет инпуты, не переключает и не трогает
лейауты (в т.ч. gold/serebro). Единственная запись — локальные файлы:
`etalons.json` (только по `--baseline`), `state.json`, `logs/watchdog.log`.

## Файлы

| Файл | Что это |
|------|---------|
| `watchdog.mjs` | сам сторож (Node, использует CDP-стек репозитория) |
| `etalons.json` | эталон: снимок 6 алертов + `expected_active` |
| `labels.json` | карта `in_N → имя инпута` по каждому pine-скрипту |
| `run-watchdog.ps1` | обёртка для Планировщика (находит node, ловит падение) |
| `install-watchdog-task.ps1` | регистрация/удаление задачи в Планировщике |
| `state.json` | анти-спам и отметка суточного OK (создаётся сам) |
| `logs/watchdog.log` | лог (UTF-8 с BOM) |

## Ручной запуск (одной командой)

Из корня репозитория `tradingview-mcp`:

```powershell
node watchdog\watchdog.mjs               # проверка + Telegram при расхождении
node watchdog\watchdog.mjs --dry         # проверка без Telegram (печать)
node watchdog\watchdog.mjs --json        # + машинный результат в stdout
node watchdog\watchdog.mjs --baseline    # ПЕРЕСНЯТЬ эталон с текущих алертов
node watchdog\watchdog.mjs --test-telegram  # проверить, что канал настроен
```

Флаг `--force` — игнорировать анти-спам (слать даже идентичное уведомление).

## Расписание (Планировщик заданий Windows)

```powershell
# зарегистрировать (2×/день, 09:15 и 21:15; без прав админа):
powershell -ExecutionPolicy Bypass -File watchdog\install-watchdog-task.ps1
# своё время:
powershell -ExecutionPolicy Bypass -File watchdog\install-watchdog-task.ps1 -Times 08:30,20:30
# прогнать сейчас:
Start-ScheduledTask -TaskName 'TV-Watchdog-Configs'
# удалить:
powershell -ExecutionPolicy Bypass -File watchdog\install-watchdog-task.ps1 -Uninstall
```

Задача запускается от текущего пользователя, только когда он в системе (TV
Desktop работает в его сессии). Требование: **TV Desktop запущен с CDP** (порт
9222). Если TV недоступен — придёт `[WATCHDOG] ⚠️ TV Desktop НЕДОСТУПЕН`.

## Уведомления в Telegram

Тот же канал, что у heartbeat бота (креды берутся из `TELEGRAM_ENV_FILE` в
`.env` бота → `D:\MY\Crypto\AI agent\.env`), префикс **`[WATCHDOG]`**. Секреты
не дублируются.

- **при расхождении** — немедленно, со списком (поток → инпут → было/стало);
  идентичное повторно не чаще `WATCHDOG_ANTISPAM_MIN` мин (по умолчанию 300);
- **суточное OK** — на чистом прогоне, один раз в день:
  `✅ watchdog OK, 6/6 алертов активны, 0 расхождений`;
- **TV недоступен** — как расхождение (не молчим).

Переменные окружения (опционально): `TV_CDP_PORT`, `WATCHDOG_ANTISPAM_MIN`,
`WATCHDOG_PREFIX`, `WATCHDOG_BOT_ENV` (путь к `.env` бота),
`WATCHDOG_TELEGRAM_BOT_TOKEN` / `WATCHDOG_TELEGRAM_CHAT_ID` (прямое переопределение).

## Пересъёмка эталона

После **осознанного** изменения конфига (поменял риск, включил фильтр, обновил
версию скрипта и пересоздал алерт) — пересними эталон, иначе сторож будет
законно ругаться:

```powershell
node watchdog\watchdog.mjs --baseline
```

`expected_active` для каждого потока задаётся в манифесте `STREAMS` внутри
`watchdog.mjs` (не снимается с живого состояния) — поэтому выключенный поток
остаётся расхождением, пока его не включат.

## Приёмка

1. В `etalons.json` у любого потока поменяй одно значение инпута (например
   `SMC EURUSD 15m` → `in_0` с `2` на `1`).
2. `node watchdog\watchdog.mjs` (или `--dry`).
3. Придёт `[WATCHDOG] ⚠️ РАСХОЖДЕНИЕ КОНФИГА` с точным именем инпута
   (`Риск на сделку, % [in_0]: 2 → 1`).
4. Верни значение обратно → следующий прогон снова `OK`.

## Коды выхода

`0` — всё сходится · `1` — есть расхождение · `2` — TV недоступен / ошибка.
