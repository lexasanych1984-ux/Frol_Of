# Проект: макрос футеровки для SolidWorks 2019

## Задача
VBA-макрос для SolidWorks 2019 (русская локализация), который в сборке по
выделенным внутренним граням кожуха промышленного теплового агрегата
(кальцинатор) строит футеровку **отдельной деталью**:
1. Создаёт виртуальную деталь "Futerovka" в начале координат сборки.
2. В контексте сборки строит эквидистантные поверхности от граней кожуха
   (по одной на слой, накопленное смещение = сумма толщин предыдущих слоёв).
3. Утолщает каждую поверхность внутрь аппарата — каждый слой отдельным телом.
4. Слои: изоляция 65 мм + рабочий слой 250 мм (задаются в начале макроса).

Текущий код: `Futerovka_v19.bas` (модуль "Futerovka", Sub main).
Прогон v18: саркофаг геометрически строится, НО (1) Combine/Полость
СБРАСЫВАЮТ цвета тел — всё серое; (2) торцы изоляции сверху/снизу
не закрыты рабочим слоем. Пользователь прислал эскиз: снаружи (к
кожуху) жёлтая изоляция, изнутри коричневый рабочий слой.
v19 = v18 + (1) финальная перекраска ВСЕХ кусков тел каждого слоя в
самом конце (ColorFeatureBodies по граням элементов утолщения — после
полости тела разрезаны на куски, красится каждый); (2) диалоги
"отметка ВЕРХА/НИЗА футеровки" (пусто = пропустить): изоляция и клон
срезаются плоскостью на OVERLAP_MM=150 от отметки ДО построения
рабочего слоя (срез только изоляции+клона: рабочего ещё нет, даже
если вырез заденет "все тела") — рабочий слой закрывает торец до
кожуха. Направление среза: константы CUT_FLIP_TOP=True /
CUT_FLIP_BOTTOM=False — НЕ ПОДТВЕРЖДЕНО прогоном, при неверной
стороне поменять местами.
v18 — РАБОЧИЙ СЛОЙ-САРКОФАГ (требование пользователя: изоляция нигде
не должна быть открыта). Схема: до 3 внутренних "слоёв" — изоляция
(эквидистанта 0, утолщение izTh), временный КЛОН изоляции (то же
самое), рабочий слой (эквидистанта 0, утолщение izTh+rabTh на полную
толщину от кожуха). Затем из рабочего вычитается клон
(InsertCombineFeature 15902, основное тело метка 1, инструменты метка
2 — записано рекордером). Клон расходуется вычитанием — ДЛЯ ЭТОГО он
и строится: Combine-Subtract уничтожает вычитаемые тела, настоящую
изоляцию вычитать нельзя. Клоны строятся вторым проходом
offset+thicken — трюк, избавивший от записи "Переместить/Копировать".
Продление листов из v17 УДАЛЕНО (тупик — см. историю). Combine-Add
15903 в коде больше не используется, но сигнатура записана и известна.
Смещения эквидистант теперь задаются массивом offMM() (все 0),
накопленное смещение больше не используется.
Открытые вопросы к пользователю (заданы): 1) у рёбер изоляция после
"Полости" упирается торцом прямо в сталь ребра — достаточно ли, или
нужен отступ 150 мм (тогда нужны отметки рёбер); 2) на верхнем крае
после ручной обрезки торец изоляции откроется — пользователь может
резать изоляцию на 150 мм ниже рабочего слоя вручную; требование
"закрывать на 150 мм" пока НЕ автоматизировано.
v15 = v14 с исправленной ошибкой компиляции: переменная iS конфликтовала
с ключевым словом VBA "Is" (v14 не компилировался). ПРАВИЛО: не называть
переменные двухбуквенными именами вида iF, iS, iN — VBA нечувствителен
к регистру и видит в них ключевые слова If, Is, In.
Прогон v15: фазы 1-3 работают, "Твердые тела(5)" — полость разрезала
цилиндровый пояс по ребру на 2 тела (ожидаемо). Обрезка верха не
выделила тела (в её коде было только 2 из 4 способов выделения).
v16 = v15 БЕЗ обрезки верха: ПОЛЬЗОВАТЕЛЬ РЕШИЛ резать верх вручную
в режиме правки. Фазу обрезки не возвращать без его просьбы.
v13 (Полость) ПОДТВЕРЖДЕНА косвенно: в записи рекордера для обрезки
тела уже назывались "Полость1[1..4]" — полость строится, рёбра режутся.
ВАЖНО: после "Полости" имена тел меняются на "Полость1[n]" (а после
обрезки, вероятно, на "СечениеN[n]") — имена тел НЕСТАБИЛЬНЫ, выделять
только объектами. Для будущего экспорта объёмов по слоям тела по именам
не найти — сопоставлять по порядку/цвету или хранить соответствие иначе.
v14 = фаза 4 "Обрезка верха": диалог отметки (мм, от начала координат
сборки; пусто/Отмена = не обрезать) -> InsertRefPlane(8, м, 0,0,0,0) от
плоскости "Сверху" -> выделение плоскости + всех тел -> InsertCutSurface
True, 0 (вызовы записаны рекордером 05.07.2026). Направление среза
(что именно отсекается — верх или низ) ЕЩЁ НЕ ПОДТВЕРЖДЕНО прогоном:
если срежет не ту сторону, менять первый аргумент InsertCutSurface
True -> False.
v10 — первая рабочая версия (механика выделения/утолщения).
v11 = толщины слоёв запрашиваются InputBox-диалогами при запуске
(0 = слой не строить, Отмена = выход).
v12 = 5-й аргумент FeatureBossThicken (bMerge) = False: с True (как в
записи рекордера) слои сливались в одно тело и изоляция "исчезала"
(в дереве "Твердые тела(2)" вместо 4). НЕ ВОЗВРАЩАТЬ bMerge=True.
ПОДТВЕРЖДЕНО прогоном v12: оба слоя отдельными телами, цвета верные.
v13 = фаза 3 "Полость": вычитание компонента кожуха (с рёбрами) из тел
футеровки в контексте сборки. Вызовы записаны рекордером (05.07.2026):
  SelectByID2("Кальцинатор поз 3-1@Футеровка поз 3", "COMPONENT",
              0,0,0, True, 0, Nothing, 0)   ' append=True, Mark=0
  ModelDoc(СБОРКИ).InsertCavity4 0, 0, 0, True, 1, -1
Выполняется в режиме EditPart2; компонент кожуха макрос берёт сам из
выделения (SelectionMgr.GetSelectedObjectsComponent4) и выделяет
объектом (Component2.Select4), а не строкой имени.
Внимание: в проекте VBA пользователя модуль не может называться
"Futerovka" (совпадает с именем проекта) — импортируется как
"Futerovka2", это нормально. Заглушку "futerovka1" (след записи
рекордера) из проекта удалить.

## КРИТИЧЕСКИЕ ПРАВИЛА
- **Файл .bas хранить строго в кодировке Windows-1251** (не UTF-8!),
  иначе русские комментарии превратятся в кракозябры при импорте в
  редактор VBA SolidWorks. При каждом редактировании сохранять cp1251.
- Пользователь — инженер-проектировщик, не программист. Он импортирует
  .bas в макрос SolidWorks (VBA-редактор -> Remove старого модуля ->
  Import File), запускает и присылает текст/скриншот ошибки.
- Ты не можешь запускать SolidWorks. Единственный источник истины —
  результаты запусков пользователя и ЗАПИСАННЫЕ им макросы (см. ниже).
- В сообщениях об ошибке макрос показывает строку "Шаг: ..." — это
  внутренний трекер gStep, точно указывающий место сбоя.

## Что УЖЕ ПРОВЕРЕНО и работает (не ломать!)

  Позднее связывание (As Object) ломает вызовы через родительские
  интерфейсы: Face2 -> Entity.Select4 давал ошибку 438.
- InsertNewVirtualPart(Nothing, comp) — создаёт виртуальную деталь в
  начале координат сборки. Работает.
- swComp.Name2 = "Futerovka" — работает.
- AssemblyDoc.EditPart2 True, True, nInfo — вход в контекст. Работает.
- Выделение граней кожуха: Set swEnt = face (As SldWorks.Entity),
  swEnt.Select4 True, Nothing. Работает.
- **InsertOffsetSurface — метод ModelDoc2, НЕ FeatureManager.**
  swAssyModel.InsertOffsetSurface dist, False — работает в контексте,
  создаёт поверхность в редактируемой детали с внешней ссылкой (->).
- Феномен: у пользователя выделенные грани кожуха НЕ смежные, поэтому
  каждая эквидистанта даёт ДВА тела поверхности (всего 4 на 2 слоя).
  Имена тел вида "Offset_Izolyaciya_65[1]" (с индексом в квадратных
  скобках — подтверждено сообщением об ошибке).
- **ЗАПИСАННЫЙ пользователем макрос (05.07.2026) подтвердил дословно**
  (запись сделана в открытом окне детали Futerovka с поверхностями):
  - выделение тела перед утолщением: `Extension.SelectByID2(
    "Offset_Izolyaciya_65[2]", "SURFACEBODY", 0, 0, 0, False, 1,
    Nothing, 0)` — метка (Mark, 7-й аргумент) = **1**, НЕ 0! В наших
    прежних попытках стояла метка 0 — вероятная причина отказов
    и/или того, что толщина "не видела" выделение.
  - сигнатура утолщения: `FeatureManager.FeatureBossThicken(
    0.065, 0, 0, False, True, True, True)` — 7 аргументов,

  Оба вызова пересажены в v9 дословно; 6-аргументный запасной вариант
  FeatureBossThicken удалён, запасное выделение Body2.Select2 теперь
  идёт с SelectData.Mark = 1.

## Что НЕ работает (история сбоев)
1. FeatureManager.InsertOffsetSurface — метода не существует (ошибка 438).
2. Body2.Select2(False, Nothing) в СБОРКЕ — возвращает False.
3. Body2.Select2(False, Nothing) в активированном окне ДЕТАЛИ — тоже False.
4. Extension.SelectByID2(bodyName, "SURFACEBODY", 0,0,0, False, **0**,
   Nothing, 0) в окне детали — False (имя "Offset_Izolyaciya_65[1]").
   С меткой 1 тот же вызов записан рекордером как рабочий (см. выше);
   влияние метки на сам результат выделения не доказано — возможно,
   тогда мешало ещё и состояние "не перестроен".
5. FeatureBossThicken при выделенном ЭЛЕМЕНТЕ (Feature.Select2) —
   вернул Nothing. Сигнатура теперь подтверждена записью (7 аргументов),
   значит дело было в выделении: нужен SURFACEBODY с Mark=1, не элемент.

## Гипотеза v8 (осталась в v9/v10, не подтверждена и не опровергнута)
Элементы с внешними ссылками (стрелка -> в дереве) после создания
в контексте находятся в состоянии "не перестроен", и их тела не
выделяются. v8+ делает ForceRebuild3 детали сразу после активации
её окна. Имена тел собираются заранее и переживают перестройку
(объектные указатели — нет). Запись эталонного макроса шла в открытой
(= перестроенной) детали, так что вреда от ForceRebuild3 нет.
